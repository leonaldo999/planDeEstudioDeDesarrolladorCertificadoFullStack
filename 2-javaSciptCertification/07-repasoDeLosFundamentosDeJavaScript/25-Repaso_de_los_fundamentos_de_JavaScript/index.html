🚀 Introducción

En esta sección, repasaremos los conceptos básicos de JavaScript que hemos visto en secciones anteriores. Estos fundamentos son esenciales para comprender cómo funciona el lenguaje y cómo podemos utilizarlo para crear aplicaciones web interactivas.

Tema 1: El constructor String y el método toString()

  • Definición: Un objeto String se utiliza para representar una secuencia de caracteres. Los objetos String se crean mediante la función constructora String, que envuelve el valor primitivo en un objeto.
1234 
const greetingObject = new String("Hello, world!");

console.log(typeof greetingObject); // "object"

Envoltura de Objetos (Object Wrapper)

Comportamiento del Constructor String:
🟢 Instanciación con new (Línea 1): Al invocar new String(), JavaScript no crea un valor primitivo regular, sino que reserva memoria para una envoltura de tipo objeto que encapsula la cadena.
🟢 Evaluación de Tipo (Línea 3): Dado que se usó el constructor como clase instanciable, el operador typeof evalúa su tipo estructural como "object" en lugar de "string".
OBJECT MEMORY INSPECTOR:
• Primitive value: "Hello, world!"
• Wrapped representation: String { "Hello, world!" }
• Type verification: "object"

💡 Recomendación de uso: En el desarrollo moderno de JavaScript casi nunca es necesario crear cadenas con new String(). Se aconseja usar siempre literales de cadena primitivos para una inicialización óptima en memoria.

  • Método toString(): Este método convierte un valor en su representación como cadena. Es un método que puedes usar con números, valores booleanos, matrices y objetos.
1234567 
const num = 10;
console.log(num.toString()); // "10"

const arr = [1, 2, 3];
console.log(arr.toString()); // "1,2,3"

Comportamiento de toString()

Resolución según Tipo de Dato:
🟢 Conversión Numérica (Línea 2): Para los números, .toString() extrae el valor primitivo y lo formatea como una cadena de texto base 10 estándar.
🟢 Conversión de Arrays (Línea 5): En arreglos, el método recorre internamente cada elemento, invoca el método de cadena de cada uno y los une de forma implícita mediante comas.
STRING CASTING REPORT:
• Number type ➔ "10" (String primitive)
• Array type ➔ "1,2,3" (Concatenated format)

💡 Curiosidad técnica: Los tipos primitivos como los números no son objetos, pero JavaScript los envuelve automáticamente en un objeto temporal (autoboxing) al invocar .toString() para que puedas acceder al método sin fallos.

  • Este método acepta un radix opcional, que es un número entre 2 y 36. Este radix representa la base, como la base 2 para el sistema binario o la base 8 para el sistema octal. Si no se especifica el radix, el valor predeterminado es la base 10, es decir, el sistema decimal.
123 
const num = 10;
console.log(num.toString(2)); // "1010"(binary)

Conversión de Base Numérica (Radix)

Mecánica del Argumento Radix:
🟢 Conversión Binaria (Línea 2): Al pasar el parámetro 2 al método .toString(), el motor de JavaScript convierte el valor decimal 10 a su representación binaria equivalente en cadena.
🟢 Cálculo de Bits: El número entero 10 se descompone matemáticamente en 8 + 2 (es decir, 1*(2³) + 0*(2²) + 1*(2¹) + 0*(2⁰)), resultando en la cadena "1010".
RADIX REPRESENTATION VISUALIZER:
• Decimal (Base 10) ➔ 10
• Binary (Base 2) ➔ "1010"
• Hexadecimal (Base 16) ➔ "a"

💡 Límite del parámetro: El parámetro radix debe ser estrictamente un entero entre 2 y 36. Si pasas un valor fuera de este rango (como 1 o 37), el motor detendrá el script lanzando un RangeError.

Tema 2: Constructor Number

  • Definición: El constructor Number se utiliza para crear un objeto numérico. El objeto numérico contiene algunas propiedades y métodos útiles, como los métodos isNaN y toFixed. En la mayoría de los casos, utilizarás el constructor Number para convertir otros tipos de datos al tipo de datos numérico.
12345678 
const myNum = new Number("34");
console.log(typeof myNum); // "object"

const num = Number('100');
console.log(num); // 100

console.log(typeof num); // number

Doble comportamiento de Number

Instanciación vs Conversión:
🟢 Instancia de Objeto (Línea 1): Al usar el operador new, se encapsula el valor dentro de un objeto envoltorio de tipo "object".
🟢 Casting Primitivo (Línea 4): Invocar el constructor directamente como una función (sin new) realiza un casting puro de tipos, retornando un valor numérico primitivo con tipo "number".
TYPE AND MEMORY AUDIT:
• new Number("34") ➔ "object" (Instancia en memoria Heap)
• Number('100') ➔ "number" (Valor primitivo directo)

💡 Regla de oro: Evita usar new Number(). Los objetos envueltos pueden causar efectos secundarios inesperados en comparaciones de igualdad estricta (===). Para realizar conversiones de tipo, usa siempre la función directa Number().

Tema 3: Mejores prácticas para nombrar variables y funciones

  • camelCasing: Por convención, los desarrolladores de JavaScript utilizan el estilo camel case para nombrar variables y funciones. En este estilo, la primera palabra se escribe completamente en minúsculas y las siguientes comienzan con mayúscula. Ejemplo: isLoading.
  • Nombres de variables booleanas: Para las variables booleanas, es una práctica común usar prefijos como "is", "has" o "can".
123 
let isLoading = true;
let hasPermission = false;
let canEdit = true;

Convenciones de Semántica y Prefijos

Análisis de Estilo Empleado:
🟢 Camel Case Estricto (Líneas 1-3): El inicio de cada variable es minúsculo, elevando a mayúscula la primera letra de cada término subsiguiente (Loading, Permission, Edit) para asegurar legibilidad inmediata.
🟢 Prefijos Descriptivos: El uso de verbos auxiliares (is, has, can) actúa como un indicador explícito que anuncia el retorno inminente de un booleano sin necesidad de revisar su asignación.
SEMANTIC RULES EVALUATION:
• isLoading ➔ Estado (¿Está cargando?)
• hasPermission ➔ Posesión (¿Tiene el permiso?)
• canEdit ➔ Habilidad (¿Puede editar?)

💡 Buenas prácticas: Nombrar booleanos usando sustantivos planos (como loading o permission) disminuye la claridad. Añadir el prefijo adecuado convierte el código en una lectura casi natural al estructurar bloques condicionales if.

  • Nombres de funciones: En el caso de las funciones, el nombre debe indicar claramente qué hace la función. Para las funciones que devuelven un valor booleano (a menudo llamadas predicados), puedes usar los mismos prefijos is, has o can. Cuando se trata de funciones que recuperan datos, es común comenzar con la palabra "get". Cuando se trata de funciones que establecen datos, es común comenzar con la palabra "set". Para las funciones de manejo de eventos, se puede usar el prefijo "handle" o el sufijo "Handler".
123456789 
function getUserData() { /* ... */ }

function isValidEmail(email) { /* ... */ }

function getProductDetails(productId) { /* ... */ }

function setUserPreferences(preferences) { /* ... */ }

function handleClick() { /* ... */ }

Semántica de Funciones y Patrones de Acción

Patrones de Nombramiento Estándar:
🟢 Acceso y Mutación (Líneas 1, 5, 7): El uso de verbos claros como get para consultas y set para asignaciones de estado define inmediatamente el flujo de datos de la función.
🟢 Predicados y Eventos (Líneas 3, 9): Prefijos de validación (is) indican retorno booleano implícito, mientras que verbos de acción directa como handle describen la captura y procesamiento de una interacción del usuario.
API DESIGN & FUNCTION INTENT:
• get... ➔ Reader (Retorna datos limpios)
• set... ➔ Writer (Modifica o escribe un estado)
• is... ➔ Evaluator (Retorna true/false)
• handle... ➔ Listener (Reacciona a eventos asíncronos)

💡 Diseño autodocumentado: Seguir estas reglas de verbos iniciales permite que cualquier desarrollador entienda el propósito de una API o módulo al instante sin tener que sumergirse a leer la implementación interna de cada función.

  • Nombres de variables dentro de los bucles: Al nombrar las variables iteradoras en los bucles, es común usar letras únicas como i, j o k.
1 
for (let i = 0; i < array.length; i++) { /* ... */ }

Variables de Iteración en Bucles

Matemática e Historia del Iterador:
🟢 Uso de la Letra "i" (Línea 1): Por convención histórica heredada de lenguajes como Fortran y de las matemáticas algebraicas, la letra i representa el concepto de "índice" o "iterador".
🟢 Orden Alfabético (j, k): En caso de requerir bucles anidados, se avanza alfabéticamente a j para el segundo nivel y a k para el tercero, manteniendo un código conciso.
LOOP SCOPING ANALYSIS:
• Iterator: i ➔ Blocked Scope (let)
• Recommended Nesting: i (outer) ➔ j (inner) ➔ k (deep)
• Scope Leakage: None (La variable no existe fuera del bucle)

💡 ¿Cuándo NO usar "i"?: Si estás iterando colecciones complejas donde el índice representa algo muy específico (como una fila o columna en una matriz de mapas), a veces es preferible usar nombres más claros como rowIndex o colIndex para evitar confusiones en el algoritmo.

Tema 4: Trabajar con matrices dispersas

  • Definición: Es posible tener matrices con celdas vacías. Las celdas vacías se definen como aquellas que no contienen nada. Esto es diferente a las celdas de una matriz cuyo valor es undefined. Este tipo de matrices se conocen como matrices dispersas.
12 
const sparseArray = [1, , , 4];
console.log(sparseArray.length); // 4

Estructura de Matrices Dispersas (Sparse Arrays)

Análisis de Ranuras Vacías (Holes):
🟢 Celdas Elididas (Línea 1): Las comas sucesivas sin valor intermedio crean ranuras vacías (empty slots). Estas celdas físicamente no existen en el mapa de propiedades del objeto Array en memoria.
🟢 Cálculo de Longitud (Línea 2): La propiedad .length no cuenta los elementos presentes, sino que simplemente retorna el índice más alto incrementado en uno, devolviendo un valor de 4.
MEMORY ALLOCATION AUDIT:
• Index 0 ➔ 1 (Allocated)
• Index 1 ➔ <empty slot> (No key in prototype)
• Index 2 ➔ <empty slot> (No key in prototype)
• Index 3 ➔ 4 (Allocated)

💡 Diferencia con undefined: Si intentas consultar el índice 1 (sparseArray[1]), el motor devolverá undefined, pero métodos iteradores nativos como .forEach() o .map() ignorarán por completo estas ranuras saltándoselas durante la ejecución.

Tema 5: Linters y formateadores

  • Linters: Un linter es una herramienta de análisis estático de código que señala errores de programación, bugs, errores de estilo y construcciones sospechosas. Un ejemplo de linter común sería ESLint.
  • Formateadores: Los formateadores son herramientas que formatean automáticamente el código para que cumpla con una guía de estilo específica. Un ejemplo de formateador común sería Prettier.
12345 
const unUsedVar = 'linter alert'; 

function badFormat(a,b){
console.log(a);
}

Análisis Estático y Estilo de Código

🔍 ESLint Alert (Análisis Calidad/Reglas):
⚠️ Línea 1: Variable declarada pero nunca usada (no-unused-vars). Puede generar fugas de memoria o código basura.
⚠️ Línea 3: Uso de var, variables globales implícitas o parámetros sin uso.
✨ Prettier Suggestions (Análisis Estético):
💅 Espaciado incorrecto (Línea 3): Falta un espacio entre los argumentos (a, b) y antes de la llave ( {} ).
💅 Indentación rota (Línea 4): El cuerpo de la función debería estar indentado con 2 o 4 espacios consistentes.

💡 Diferencia Clave: Un **Linter** (ESLint) se enfoca en la **calidad del código** (encontrar bugs potenciales y malas prácticas de lógica). Un **Formateador** (Prettier) se encarga exclusivamente de la **consistencia visual** (comas, espacios, comillas simples/dobles e indentaciones).

Tema 6: Administración de memoria

  • Definición: La administración de memoria es el proceso de controlar la memoria, asignarla cuando sea necesario y liberarla cuando ya no se necesite. JavaScript utiliza una administración automática de memoria. Esto significa que JavaScript (más específicamente, el motor de JavaScript de tu navegador web) se encarga de la asignación y liberación de memoria por ti. No es necesario que liberes memoria explícitamente en tu código. A este proceso automático se le suele llamar "recolección de basura".

Tema 7: Cierres

  • Definición: Un cierre es una función que tiene acceso a las variables de su ámbito léxico externo (en el que está contenida), incluso después de que la función externa haya finalizado.
1234567891011 
function outerFunction(x) {
  let y = 10;
  function innerFunction() {
    console.log(x + y);
  }
  return innerFunction;
}

let closure = outerFunction(5);
closure(); // 15

Persistencia del Ámbito Léxico (Closure)

Ciclo de Vida de las Variables:
🟢 Retención de Memoria (Línea 4): Aunque outerFunction finaliza su ejecución en la línea 9, innerFunction mantiene viva una referencia interna a x (del parámetro) y a y (del ámbito local).
🟢 Resolución en Ejecución (Línea 10): Al llamar a closure(), el motor de JS busca las referencias en el "entorno de cierre" guardado en memoria, resolviendo con éxito el cálculo 5 + 10.
SCOPE CHAIN DIAGRAM:
• Closure Scope ➔ { x: 5, y: 10 } (Preservado)
• Local Scope (innerFunction) ➔ {} (Vacío)
• Output Console ➔ 15

💡 Manejo de memoria: Los closures evitan que el recolector de basura (*Garbage Collector*) libere el ámbito de la función externa. Úsalos de manera consciente para evitar retenciones accidentales de memoria en estructuras de datos muy grandes.

Tema 8: La palabra clave var y el hoisting

  • Definición: var era la forma original de declarar variables antes de 2015. Sin embargo, var presentaba algunos problemas relacionados con el ámbito, la redeclaración y otros aspectos. Por eso, en la programación moderna de JavaScript se utilizan let y const en su lugar. Redeclaración de variables con var: Si intentas redeclarar una variable usando let, obtendrás un SyntaxError. Sin embargo, con var, sí se permite redeclarar una variable.
123456789 
// Uncaught SyntaxError: Identifier 'num' has already been declared 
let num = 19;
let num = 18;

var myNum = 5;
var myNum = 10; // This is allowed and doesn't throw an error

console.log(myNum) // 10

Reglas de Ámbito y Redeclaración

Análisis de Comportamiento:
🔴 Bloqueo Sintáctico (Línea 3): El motor de JavaScript impide por completo que let registre un identificador idéntico en el mismo contexto, interrumpiendo la lectura de inmediato.
🟢 Mutación Permisiva (Línea 6): Al procesar var, el compilador ignora la segunda declaración física y la interpreta simplemente como una reasignación directa de valor sobre la variable existente en memoria.
PARSING RUNTIME REPORT:
• Lexical Check: let num ➔ SyntaxError (Línea 3)
• Identifier Override: myNum ➔ Reescrito de 5 a 10
• Console Output: ➔ 10

💡 ¿Por qué evitar var?: Permitir la redeclaración silenciosa facilita la aparición de bugs invisibles, donde puedes sobrescribir accidentalmente variables globales o locales previamente configuradas sin recibir ningún aviso o mensaje de error.

  • var y el ámbito: Las variables declaradas con var dentro de un bloque (como una instrucción if o un ciclo for) siguen siendo accesibles fuera de ese bloque.
12345 
if (true) {
  var num = 5;
}

console.log(num); // 5

Comportamiento del Ámbito en Bloques

Fuga de Ámbito (Scope Leakage):
🟢 Ámbito Funcional (Línea 2): Dado que var ignora los bloques estructurados (como if, for o while) y solo se limita por funciones, la variable se registra en el contexto global o de la función contenedora.
🟢 Acceso Externo (Línea 5): La variable num escapa de las llaves del bloque condicional, permitiendo que la llamada externa la lea sin lanzar un error de referencia.
SCOPE RESOLUTION AUDIT:
• Block Scope (if) ➔ No aplica para var
• Outer/Global Scope ➔ { num: 5 } (Asignado globalmente)
• Console Output ➔ 5

💡 Diferencia con let y const: Si hubieras usado let o const, la variable habría quedado estrictamente restringida al interior del bloque if, y la línea 5 habría fallado de inmediato con un ReferenceError.

  • Cuando declaras una función utilizando la sintaxis de declaración de funciones, tanto el nombre como el cuerpo de la función se elevan. Esto significa que puedes llamar a una función antes de haberla declarado en tu código.
12345 
sayHello(); // "Hello, World!"

function sayHello() {
  console.log("Hello, World!");
}

Elevación de Funciones (Function Hoisting)

Fase de Compilación vs. Ejecución:
🟢 Registro Completo (Líneas 3-5): Durante la fase de creación del contexto, el motor de JS registra en memoria tanto el identificador sayHello como su definición física completa.
🟢 Invocación Temprana (Línea 1): Al iniciar la fase de ejecución paso a paso, la función ya está totalmente asignada y disponible para ser invocada con éxito antes de su definición textual.
INTERPRETER TIMELINE:
• Step 1 (Compile) ➔ Reservar espacio para sayHello() { ... }
• Step 2 (Execute) ➔ Ejecutar sayHello() en la Línea 1
• Output Console ➔ "Hello, World!"

💡 Expresiones de función: Ten en cuenta que este comportamiento solo aplica a las **declaraciones tradicionales**. Si asignas una función a una variable (const sayHello = () => ...), el hoisting no elevará la definición y arrojará un error si intentas llamarla previamente.

  • Las declaraciones de variables realizadas con let o const se elevan, pero no se inicializan, y no puedes acceder a ellas antes de la declaración real en tu código. A este comportamiento se le suele llamar "zona muerta temporal".
12 
console.log(num); // Throws a ReferenceError
let num = 10;

Zona Muerta Temporal (TDZ)

Análisis de Inicialización:
🔴 Falta de Inicialización (Línea 1): Aunque let num es reconocida por el compilador en la fase previa, entra en un estado "no inicializado". El acceso temprano a su identificador está estrictamente prohibido.
🟢 Activación Léxica (Línea 2): La variable sale de la Zona Muerta Temporal solo cuando el flujo de ejecución pasa físicamente por encima de la línea de su asignación de valor inicial.
TDZ RUNTIME EXCEPTION:
• Line 1 ➔ num in TDZ (Estado inaccesible)
• Execution Status ➔ ReferenceError: Cannot access 'num' before initialization

💡 Diferencia crucial con var: A diferencia de var (que se inicializa automáticamente en memoria como undefined durante el hoisting), let y const te obligan a escribir un código lineal y ordenado, evitando errores lógicos por leer variables antes de tiempo.

Tema 9: Administración de memoria

  • Módulo: Es una unidad de código independiente que encapsula funciones, clases o variables relacionadas. Para crear un módulo, debes escribir tu código JavaScript en un archivo aparte.
  • Exportaciones: Cualquier variable, función o clase que desees que esté disponible para otras partes de tu aplicación debe exportarse explícitamente utilizando la palabra clave export. Existen dos tipos de exportación: la exportación con nombre y la exportación por defecto.
  • Importaciones: Para utilizar los elementos exportados en otra parte de la aplicación, es necesario importarlos mediante la palabra clave import. Los tipos pueden ser importación con nombre, importación por defecto e importación de espacio de nombres.
123456789101112131415161718 
// Within another file, we can import the functions from math.js.

// Named import - This line imports the add function.
// The name of the function must exactly match the one exported from math.js.
import { add } from './math.js';

// Default import - This line imports the subtract function.
// The name of the function can be anything.
import subtractFunc from './math.js';

// Namespace import - This line imports everything from the file.
import * as Math from './math.js';

console.log(add(5, 3)); // 8
console.log(subtractFunc(5, 3)); // 2
console.log(Math.add(5, 3)); // 8
console.log(Math.subtract(5, 3)); // 2
12345678910111213 
// Within a file called math.js, we export the following functions:

// Named export
export function add(num1, num2) {
  return num1 + num2;
}

// Default export
export default function subtract(num1, num2) {
  return num1 - num2;
}

Resolución de Importación y Exportación (ESM)

Comparativa de Enlaces:
📦 Export Nombrado (Named): Obliga al importador a utilizar llaves { add } y a mantener exactamente el mismo identificador definido en el origen.
⭐️ Export por Defecto (Default): Solo puede existir un único export default por archivo. Se puede importar sin llaves y se le puede asignar cualquier nombre arbitrario como subtractFunc.
🌐 Namespace Import (*): Empaqueta todas las exportaciones (incluido el default) bajo un único objeto namespace estructurado (Math).
MODULAR TERMINAL OUTPUT:
• Line 14: add(5, 3) ➔ 8
• Line 15: subtractFunc(5, 3) ➔ 2
• Line 16: Math.add(5, 3) ➔ 8
• Line 17: Math.subtract(5, 3) ➔ 2

💡 Uso en entornos web: Para utilizar la sintaxis import / export directamente en el navegador, debes añadir el atributo type="module" a tu etiqueta script en el archivo HTML.
